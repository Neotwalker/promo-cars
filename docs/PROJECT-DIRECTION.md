# Project Direction

Этот документ — основной источник решений по проекту. Перед крупными изменениями сверяться с ним.

## Цель

Создать современный промо-лендинг для сервиса подбора и доставки автомобилей из Китая и других стран Азии в Россию.

## Утверждённый бренд

Рабочий бренд презентационной версии: **NEXROUTE AUTO**.

Брендовая идея:
- автомобиль выбирает пользователь;
- NEXROUTE управляет понятным маршрутом сделки до выдачи;
- интерфейс строится вокруг route / status / documents / handover;
- автомобильный контент должен быть эмоциональным и premium, а блоки доверия — доказательными и предметными.

Подробная концепция, tone of voice и asset direction: [BRAND-CONCEPTS.md](BRAND-CONCEPTS.md).

Сайт должен:
- выглядеть дорого и современно;
- не быть копией исходного референса;
- сохранять автомобильную тематику;
- объяснять процесс покупки и доставки;
- снижать тревогу перед дорогой сделкой;
- вести пользователя к расчёту и заявке;
- оставаться визуально цельным при изменении ширины viewport.

## Базовая визуальная идея

Рабочее направление — автомобиль + маршрут + статус сделки.

Ключевые визуальные сущности:
- автомобиль;
- маршрут;
- страна / город;
- ETA;
- этап сделки;
- статус;
- стоимость;
- проверка автомобиля;
- документы;
- логистика;
- выдача.

Использовать это как визуальный язык сайта вместо шаблонной стилистики автосалона.

## UI-kit

UI-kit является основой сайта.

В нём зафиксированы:
- цветовые токены;
- типографическая шкала;
- 12-колоночная сетка;
- spacing-system;
- кнопки;
- controls;
- hover / active / focus states;
- формы;
- карточки автомобилей;
- маршрутные карточки;
- статусы;
- marquee;
- motion-patterns;
- reduced-motion;
- desktop/tablet/mobile rules.

Публичный UI-kit должен оставаться автомобильным, но без:
- названий внутренних этапов разработки;
- упоминаний референса;
- screen recording;
- формулировок вида redesign v2;
- служебных комментариев о процессе создания.

## Масштабирование

На desktop использовать единую координатную систему по принципу fluid-layout.

Базовая идея:

```css
html {
  font-size: clamp(9px, calc(100vw / 192), 11.5px);
}
```

На ширине 1920 px:
- 1rem ≈ 10px.

Desktop-композиция должна масштабироваться как единое полотно.

До 1100 px:
- отдельная tablet/mobile-композиция;
- не пытаться просто уменьшать desktop;
- в landscape на 821–1100 px допустима более плотная двухколоночная tablet-композиция для ключевых секций, если она сохраняет читаемость и touch-friendly размеры;
- в landscape до 820 px используется отдельный компактный вертикальный ритм; на 641–820 px отдельные крупные блоки могут возвращаться к двум колонкам, если контент не становится тесным.

Не смешивать без необходимости множество независимых clamp(), vw, px и max-width для ключевых элементов одной композиции.

## Предлагаемая структура страницы

### 1. Hero

Задача:
- сразу показать автомобильную тематику;
- создать ощущение технологичного и надёжного сервиса;
- объяснить основной оффер;
- привести к расчёту.

Направление:
- крупный автомобиль;
- маршрутные данные;
- статус / ETA / страна;
- большая типографика;
- motion, связанный с автомобилем или маршрутом.

Не делать Three.js только ради эффекта.

3D использовать только если:
- есть качественная модель;
- взаимодействие усиливает смысл;
- performance остаётся хорошим.

Видео / image-sequence / layered motion допустимы и могут быть предпочтительнее.

### 2. Быстрое доказательство выгоды

Задача:
- объяснить, зачем заказывать автомобиль через сервис.

Возможные данные:
- экономия;
- сроки;
- количество доставленных авто;
- договор;
- страховка;
- прозрачность платежей.

Не перегружать блок большим количеством одинаковых карточек.

### 3. Реальные автомобили

Задача:
- показать реальные или реалистично оформленные кейсы доставки.

Карточка может содержать:
- модель;
- год;
- пробег;
- страна;
- маршрут;
- срок;
- цена;
- статус;
- фото / видео.

Контент должен выглядеть как единая серия, а не случайный набор stock-фото.

### 4. Путь автомобиля

Один из ключевых интерактивных блоков.

Этапы:
1. Подбор.
2. Проверка / видеоотчёт.
3. Выкуп.
4. Страхование.
5. Доставка до границы.
6. Таможенное оформление.
7. ЭПТС.
8. Доставка клиенту.

Направление:
- sticky / scroll-driven section;
- маршрут развивается вместе со скроллом;
- автомобиль или marker движется по пути;
- текущий этап подсвечивается;
- справа или поверх меняются данные.

Motion должен объяснять процесс, а не быть декоративным.

### 5. Калькулятор стоимости

Один из главных conversion-блоков сайта.

Не обычная длинная форма.

Формат:
- пошаговый конфигуратор / quiz;
- плавная смена шагов;
- визуальная обратная связь;
- progress;
- понятный итог.

Возможные шаги:
1. Автомобиль / марка / тип кузова.
2. Новый или б/у.
3. Бюджет.
4. Город доставки.
5. Контакт.

Если нет точной формулы расчёта:
- не имитировать точный расчёт;
- показывать предварительный диапазон;
- запрашивать контакт для точной сметы.

Можно использовать состояние:
«Рассчитываем логистику, пошлину и утильсбор…»

## 6. Живой контент / доверие

Очень высокий приоритет.

Не ограничиваться обычными отзывами.

Сделать bento-сетку с материалами:
- видеоосмотр автомобиля;
- машина на площадке;
- менеджер;
- автовоз;
- граница;
- документы;
- выдача автомобиля;
- клиент с ключами;
- короткий отзыв;
- фактические цифры.

Реальные материалы предпочтительнее stock-фото.

## 7. Гарантии / безопасность сделки

Закрыть основные страхи:
- деньги;
- состояние машины;
- сроки;
- документы;
- повреждение в пути;
- неизвестность процесса.

Можно использовать:
- договор;
- страховку;
- проверку;
- этапность платежей;
- фото / видеоотчёты;
- прозрачный статус сделки.

## 8. Отзывы

Отзывы должны поддерживать доверие, а не просто занимать место.

Лучше:
- фото;
- модель автомобиля;
- город;
- короткая цитата;
- ссылка / видео при наличии.

## 9. FAQ

Только реальные вопросы пользователя:
- итоговая стоимость;
- сроки;
- оплата;
- гарантии;
- растаможка;
- ЭПТС;
- доставка в город;
- что происходит при отказе от автомобиля;
- кто отвечает за повреждение в пути.

## 10. Final CTA

Финальный экран должен визуально завершать маршрут.

Идея:
- автомобиль прибыл;
- статус DELIVERY COMPLETE / READY FOR HANDOVER;
- крупный CTA на расчёт или подбор.

## Интерактив и motion

Использовать:
- masked text reveal;
- scroll-driven progress;
- route animation;
- continuous marquee;
- card hover;
- image zoom;
- status transitions;
- meaningful microinteractions.

Не использовать:
- случайные fade-in в каждом блоке;
- чрезмерный glow;
- бесцельный glassmorphism;
- постоянные bounce-анимации;
- эффекты только потому, что они «трендовые».

## Bento

Bento подходит для:
- живого контента;
- преимуществ;
- документов;
- цифр;
- видео;
- trust-блока.

Не превращать весь сайт в bento.

## Glass

Использовать точечно:
- карточки поверх фото / видео;
- route/status UI;
- process cards.

Не использовать как универсальный фон для всех карточек.

## Custom cursor

Допустим только в интерактивных media-зонах:
- видео;
- галерея;
- drag;
- carousel.

Не заменять обычный курсор на всём сайте.

## Контент

Предпочтение:
- реальные автомобили;
- реальные площадки;
- реальные документы;
- реальные видео;
- реальные отзывы.

Временные placeholders допустимы на этапе разработки, но структура должна сразу проектироваться под реальные материалы.

## Технологический подход

Текущий UI-kit и прототип могут оставаться на чистом HTML/CSS/JS.

React / Next / Three.js подключать только если они дают реальное преимущество:
- сложный калькулятор;
- много состояний;
- сложный 3D;
- CMS/API;
- масштабирование проекта.

Не менять стек только ради модности.

## Правила разработки

1. Сначала проектировать структуру и композицию, потом полировать эффекты.
2. Не переделывать сразу весь сайт после одного визуального замечания.
3. Проверять блоки по одному.
4. Не ломать рабочие секции при исправлении соседних.
5. Использовать UI-kit как источник токенов и компонентов.
6. Новые компоненты сначала добавлять в UI-kit, если они повторно используются.
7. Для marquee использовать проверенную динамическую логику с измерением группы и клонами.
8. Поддерживать reduced-motion.
9. Не добавлять неподтверждённые цифры как факты.
10. Не делать интерфейс похожим на исходный референс намеренно.

## Порядок дальнейшей работы

1. Утвердить этот документ.
2. Сделать структурный wireframe всей страницы.
3. Зафиксировать тексты / данные-заглушки для каждого блока.
4. Сделать hero-концепцию.
5. Собрать преимущества.
6. Собрать реальные автомобили.
7. Сделать scroll-driven «Путь автомобиля».
8. Сделать калькулятор.
9. Сделать trust / live-content bento.
10. Сделать гарантии.
11. Сделать отзывы.
12. Сделать FAQ.
13. Сделать final CTA.
14. Responsive QA.
15. Motion QA.
16. Performance / accessibility QA.

## Главный критерий

Сайт должен восприниматься как единая современная цифровая система вокруг покупки и доставки автомобиля, а не как набор красивых секций.
